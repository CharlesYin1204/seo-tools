**短信宝HTTP API接口规范：**
- 接口地址：http://api.smsbao.com/sms
- 请求方式：GET
- 字符编码：UTF-8

**必需参数：**
- u：用户名（短信宝账号用户名）
- p：密码（MD5加密后的32位小写密码）
- m：手机号码（单个号码或多个号码用英文逗号分隔）
- c：短信内容（需要URL编码）

**短信内容格式：**
【签名】+短信正文
- 签名长度：3-10个字符
- 签名内容：公司简称、网站简称或注册商标名称

**返回值说明：**
- 0：发送成功
- -1：参数不全
- -2：服务器空间不支持
- 30：密码错误
- 40：账号不存在
- 41：余额不足
- 42：账户已过期
- 43：IP地址限制
- 50：内容含有敏感词
- 51：手机号码不正确

**后台配置项：**
1. 短信宝用户名
2. 短信宝密码
3. 短信签名（3-10个字符）

9，Ahrefs 外链权威 API：使用 API v3 `GET https://api.ahrefs.com/v3/public/domain-rating-free?target={host}&output=json`，请求头为 `Authorization: Bearer {token}`。返回 `domain_rating.domain_rating` 作为外链权威分值；Token 仅允许管理员后台配置并由服务端调用。

Ahrefs 成功结果按 `normalized_host + provider` 写入 `seo_authority_metrics`。在管理员配置的刷新周期内直接读取缓存；周期过期后调用 API，失败则返回最近真实值并标记 `authorityStatus=stale`，不存在历史值时返回空分值。

10，SEO 证据分析接口：`POST /api/user/seo/features/:module/analyze`，其中 `module` 仅允许 `content`、`internal-links`、`schema`、`geo`。请求 URL 必须精确匹配当前组织最近扫描写入的 `seo_pages.url`，禁止分析其他组织或未扫描 URL。

11，发布前检查接口：`POST /api/user/seo/candidates/:id/publish-check`。仅接受已批准候选；没有通过审核的可写连接器时返回 HTTP 409，不写入虚假发布成功记录。旧 `/publish-simulated` 路径仅作为兼容别名。

12，Google Search Console 导入：`GET /api/user/seo/sites/:id/gsc/authorize` 创建一次性 OAuth state；Google 回调 `GET /api/user/seo/gsc/callback` 使用 `https://oauth2.googleapis.com/token` 交换授权码，再调用 `GET https://www.googleapis.com/webmasters/v3/sites`。仅导入与站点主机精确匹配且权限不是 `siteUnverifiedUser` 的 property；导入不会改变本站所有权验证状态。

Google OAuth 配置优先读取管理员后台系统设置 `auth_google_client_id`、`auth_google_client_secret`、`auth_google_gsc_callback_url`，环境变量仅作为部署兼容后备。回调地址必须与 Google Cloud OAuth 客户端中登记的 Redirect URI 完全一致。

13，SEO 发布连接器协议：连接器必须是已验证站点同域名下的 HTTPS 地址，支持 `Bearer`、`Basic`、`HMAC-SHA256` 或无认证。健康检查和发布均使用 `POST application/json`。健康检查请求为 `{"action":"health_check","site_id":数字}`；发布请求为 `{"action":"update_metadata","candidate_id":数字,"url":"原页面URL","title":"候选标题","meta_description":"候选描述"}`。连接器必须返回 HTTP 2xx；HMAC 请求头为 `X-SEOAI-Timestamp` 和 `X-SEOAI-Signature`，签名原文为 `{timestamp}.{原始JSON请求体}`。凭据使用 AES-256-GCM 加密存储，API 与审计日志均不得回显。

14，真实发布与复扫：`POST /api/user/seo/candidates/:id/publish-check` 将候选状态原子切换为 `publishing`，调用最近通过健康检查的活动连接器，并使用安全抓取器重新读取原 URL。只有实际 Title 和 Meta Description 均与候选完全一致时状态变为 `published`；否则为 `publish_failed`，允许修复缓存或连接器后重试。每次尝试写入 `seo_publish_jobs`，记录远端 HTTP 状态、响应摘要和复扫证据。
# 前端 API 基址约定（2026-09-04）

- 生产构建未显式设置 `VITE_API_BASE_URL` 时，前端统一使用 `/api`，避免 SPA 页面路径与接口路径发生冲突。
- 认证、用户中心和管理员接口分别同时由 `/api/auth`、`/api/user`、`/api/admin` 提供；登录态、用户资料和业务接口使用同一请求基址。

15，SEO 专项分析：`POST /api/user/seo/features/:module/analyze` 的 `module` 支持 `content`、`internal-links`、`schema`、`geo`。前端必须从 `GET /api/user/seo/pages` 返回的已扫描页面中选择 URL，后端再次按 `organization_id + 精确 URL` 校验，禁止模型或用户输入替换目标 URL。分析结果写入 `seo_feature_analyses`，返回最近 10 次同页面同模块记录。

- 内容简报：使用最近扫描保存的正文字符数、正文摘要、H1/H2/H3、Title、Description 和问题证据生成。
- 内链建议：读取锚文本、nofollow 和规范化目标地址，仅在同站、同扫描批次、非当前页面中产生候选。
- Schema：解析实际 JSON-LD，逐块校验 `@context`、`@type`，候选仅使用页面现有 URL、Title 和 Description。
- GEO：实时读取 `/llms.txt`、`/robots.txt`，检查 GPTBot、Google-Extended、ClaudeBot、PerplexityBot 规则，并结合页面索引、结构化数据、正文和标题层级计算证据分。

16，发布工作区：`GET /api/user/seo/publishing` 按当前组织聚合已批准、已导出、发布中、发布成功及发布失败候选，同时返回脱敏连接器状态和 `seo_publish_jobs` 执行证据。接口不得返回 `credentials_encrypted`。候选导出是交付方式之一，不应阻止后续真实发布，因此 `approved`、`exported`、`publish_failed` 均可进入发布锁；未找到活动且最近健康检查为 HTTP 2xx 的连接器时返回 409，候选状态和任务数量保持不变。

17，Google Search Console 数据闭环：OAuth 回调匹配 property 后，使用 Search Analytics API 导入最近 28 天按日期聚合的点击、曝光、CTR、平均排名，并使用 URL Inspection API 检查站点首页索引状态。连接保存到 `seo_gsc_connections`，每日指标保存到 `seo_gsc_daily_metrics`；access token 与 refresh token 使用 AES-256-GCM 加密，任何用户接口均不得返回令牌字段。

- `POST /api/user/seo/sites/:id/gsc/sync`：刷新即将过期的 access token，同步真实指标和索引状态，写入审计日志。
- `DELETE /api/user/seo/sites/:id/gsc`：将连接标记为断开，覆盖加密令牌并删除本站本地 GSC 指标。
- OAuth `state` 由服务器 Session 保存，回调在登录中间件之前注册，但必须通过一次性 state、10 分钟有效期、组织和站点四重校验。
